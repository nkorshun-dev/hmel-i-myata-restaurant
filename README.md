# Хмель и Мята — сайт ресторана с бронью по схеме зала

Демо-проект для портфолио: вымышленный ресторан современной белорусской кухни и крафтового пива в Минске. Можно выбрать не просто время, а конкретный столик на интерактивной схеме зала. Бизнес вымышленный, брони никуда не отправляются.

Демо: https://nkorshun-restaurant.netlify.app.

## Что умеет

- Схема зала в инлайн SVG, строится из данных: два зала («Основной» и «Веранда», веранда с мая по сентябрь) и барная стойка. Столики на 2, 4, 6 и 8 мест, круглые и прямоугольные.
- Бронь в 3 шага: параметры, столик на схеме, контакты. Экран успеха с номером брони, `.ics` для календаря и отменой.
- Занятость столиков считается детерминированно по дате и времени, брони пользователя из localStorage тоже занимают столики.
- Меню на 42 позиции: фильтры по меткам и аллергенам, поиск без учёта регистра и «ё», фильтры в URL, модалка блюда с пивом к нему, раздел «Пиво на кране» (14 сортов).
- Главная: hero, о нас, хиты, бизнес-ланч с вкладками Пн–Пт, превью схемы, банкеты с заявкой, отзывы со свайпом, FAQ, контакты с картой OpenStreetMap.
- Доступность: столики на схеме — кнопки с `aria-label` («Столик 7, 4 места, у окна, свободен»), Tab и стрелки между столиками, Enter выбирает, `aria-live` для сводки, видимый фокус, `prefers-reduced-motion`.
- SEO: title, description, Open Graph, canonical, `lang="ru"`, JSON-LD `Restaurant` с меню и часами, SVG-favicon.

## Стек

HTML5, CSS3, ванильный JavaScript (ES-модули), SVG. Без сборки и зависимостей. Шрифты Playfair Display и Manrope (Google Fonts), фото Unsplash.

## Как устроена схема зала

`js/floor-data.js` описывает залы (`HALLS`), декор (`DECOR`: окна, камин, бар, растения) и столики (`TABLES`: id, номер, зал, вместимость, форма, зона, координаты центра). `js/floor.js` превращает эти данные в строку SVG: для каждого столика рисуются стулья, форма и номер. Это не картинка, поэтому столики можно фокусировать, подписывать для скринридера и перекрашивать по статусу. Масштаб меняется через `viewBox`: кнопки +/−, pinch двумя пальцами и перетаскивание в увеличенном виде.

Статусы столика: `free`, `busy`, `small` («мало мест»), `big` («слишком большой столик»), `closed` (зал закрыт). Подходят столики на `гостей … гостей+2` мест.

## Как считается занятость

`js/availability.js`, только чистые функции:

1. Для пары (столик, дата) строится список «чужих» броней. Идём по слотам по 30 минут; в каждом слоте бросается детерминированная «монетка»: хеш FNV-1a от строки `столик|дата|слот` сравнивается с вероятностью. Вероятность выше вечером и в пт–сб. После брони следующий слот ищется не раньше чем через 2 часа.
2. Бронь занимает столик на 2 часа: интервалы `[s, s+120)` и `[t, t+120)` пересекаются, если `|s − t| < 120`. Поэтому столик, занятый на 19:00, свободен на 21:30.
3. Брони пользователя (localStorage, ключ `hm_bookings`) проверяются тем же правилом.
4. Результат не зависит от времени запуска и одинаков при перезагрузке.

Дата и время «сейчас» берутся по Минску (Europe/Minsk), а не по часовому поясу посетителя; в `.ics` время переводится в UTC.

Слоты: от открытия до «закрытие − 2 часа». Часы: Пн–Чт 12:00–23:00, Пт–Сб 12:00–01:00, Вс 12:00–22:00.

## Где менять

- Меню и пиво: `js/menu-data.js` (строки `D(...)` и `B(...)`).
- Столики и декор: `js/floor-data.js`.
- Часы работы и сезон веранды: `workingHours` и `SEASON` в `js/availability.js`.
- Отзывы, FAQ, ланч, банкеты, контакты: `js/content-data.js`.
- Цвета и шрифты: переменные в начале `css/styles.css`.
- Депозит (30 BYN с человека от 6 гостей): константа `DEPOSIT` в `js/booking.js`.

## Запуск локально

```bash
npx serve -l 5195 .
```

Открыть http://localhost:5195. Нужен любой статический сервер, ES-модули не работают с `file://`.

## Деплой на Netlify

1. Залить папку в репозиторий (или перетащить в Netlify Drop).
2. Build command пустой, publish directory `.` (уже в `netlify.toml`).
3. В `netlify.toml` настроены заголовки безопасности (CSP, X-Frame-Options и др.) и кэширование. `404.html` Netlify подхватывает сам.
4. Замените домен `nkorshun-restaurant.netlify.app` в canonical и Open Graph на свой.

## Проверка

Чистая логика (занятость, вместимость, фильтры, маска телефона, валидация) проверяется небольшим node-скриптом. Lighthouse и тесты на реальном телефоне нужно прогнать вручную после деплоя.
